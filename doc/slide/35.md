***35: Memory Operations***

```py
# `, ( cell -- )` append cell to end of allocated @ref M
def compile(): M.append(pop())

## `@ ( addr -- cell )` fetch object from @ref M using integer index
def fetch(): push(M[pop()])

## `! ( cell addr -- )` store object to @ref M
def store(): addr = pop(); M[addr] = pop()
```

## subtitles
### ru

В классических форт-системах используется низкоуровневый побайтовый доступ к
памяти, и словарь также расположен внутри адресного пространства.

Так как мы реализуем на питоне высокоуровневую модель форт-системы, есть
определённая сложность, как разложить регионы памяти по высокоуровневым
структурам данных, нативных для языка.

Например, можно полностью отказаться от памяти, адресуемой целочисленными
индексами или адресами, и использовать словарь как основную и единственную
структуру хранения.

В нашем варианте для эм-памяти используется список, чтобы сохранить
целочисленную адресацию. А для словаря выбрана отдельная структура -- дикт, то
есть Python-словарь. Такое разделение может быть применено и в случае, когда вы
хотите компилировать программы более устойчивые к реверс-инжинирингу. Клиенту
отдается бинарный файл, не содержащий информацию из словаря, что усложнит
восстановление или модификацию логики программы.

Для доступа к памяти форт-системы как минимум необходимо два слова:
- фетч, или символ собаки: с вершины стека берётся адрес, и заменяется на стеке
  значением из памяти
- стор, или символ восклицательного знака: на стеке лежит значение и адрес,
  которые снимаются со стека при записи в память

В низкоуровневом Форте память выделяется с нижних нулевых адресов вверх, и
память  делится на две части -- занятую словарём, данными и кодом, и
неаллоцированную.

В нашем высокоуровневом варианте тоже есть подобная ситуация: основная память
расположена в списке расширяющейся длины. Можно либо обращаться к уже
существующим элементам, либо добавить новый элемент в конец памяти.
